4. 实现双击超级加速时忘记记录按键时间戳，无法判断两次按下是否在短时间内，导致双击检测失败

### （7） 用自己话解释至少 2 处 AI 生成代码的关键逻辑：
1. 逻辑一：蛇的移动
蛇用数组存，头在索引 0，尾在最后；每步 unshift 加新头，没吃就 pop 删尾；吃了就不删，数组长度 +1 就是变长。

2. 逻辑一：BFS 寻路
BFS 从蛇头开始，向上下左右四个方向均匀扩散，像水漫开。visited 记录走过的格子，防止重复；parent 记录每格从哪来。第一次碰到食物时，从食物倒推回蛇头，得到整条最短路径。但蛇每走一步，身体和食物都可能变，旧路径会过期，所以每帧只取路径第 2 格当下一步，然后重新算。

3. 逻辑二：安全判定
BFS 找到路不代表安全，可能吃完就把自己围死。安全判定先复制一份蛇，模拟走完整条路径，看未来状态下蛇头还能不能到蛇尾。能到，说明有退路，走；不能到，放弃这条路径，改去找尾巴。如果所有安全走法都不存在，就选可达空间最大的，容错最高。

## 四、贪吃蛇
### （1） 新增功能 ：计分制
1. 怎么实现：
用 localStorage 存三个值：snakeHigh（最高分）、snakeGames（局数）、snakeHistory（战绩数组）。每局结束调用 endRound()，如果当前得分高于最高分就更新；新一局开始时得分归零，但最高分和局数不清零。工具栏加了一个「重置」按钮，点击后清空所有记录并确认。

2. 怎么验证：
玩一局得 3 分，刷新页面再玩一局得 5 分，页面显示最高分 5、局数 2。点击「重置」并确认，所有数据归零。

3. 提示词迭代：
我让 AI 加计分功能，AI 一开始只在页面显示当前分数，没存最高分。我补了一句“最高分和局数要用 localStorage 存，刷新不丢”，AI 就改对了。

### （2） 新增功能 ：主题切换
1. 怎么实现：
用 CSS 变量定义两套配色：body[data-theme="dark"] 和 body[data-theme="light"]。点击「切换浅色/深色」按钮时，调用 applyTheme() 修改 <body> 的 data-theme 属性，CSS 变量自动切换。选中的主题存进 localStorage，刷新后自动应用。

2. 怎么验证：
点击按钮，页面颜色立即从深色变浅色。刷新页面，仍然是浅色。再点一次，变回深色。

3. 提示词迭代：
我让 AI 加主题切换，AI 写了一个按钮但刷新后不保留。我提示“用 localStorage 存主题”，AI 就加了持久化逻辑。

### （3） 新增功能 ：多局战绩记录
1. 怎么实现：
用 localStorage 存一个 snakeHistory 数组。每局结束时，把“第几局、成功还是失败、得分、时间”追加进去，只保留最近 10 条（超过就 shift() 删掉最旧的）。点击「查看战绩」按钮，用 renderHistory() 把数组渲染成列表，弹窗显示。

2. 怎么验证：
玩 3 局后点击「查看战绩」，能看到 3 条记录。再玩 12 局，列表只显示最近 10 条，顺序是从新到旧。

3. 提示词迭代：
我让 AI 加战绩记录，AI 一开始把记录存在内存里，刷新就没了。我提示“和计分一样用 localStorage”，AI 就改对了。

### （4） 新增功能 ：倍速框
1. 怎么实现：
右侧有一个「当前倍速」面板，包含数字输入框和「应用」按钮。userSpeed 变量控制 setInterval 的间隔，默认 80 毫秒。输入倍率后，applyInputSpeed() 计算 userSpeed = Math.max(1, 80 / mult)，然后重启定时器。倍率显示会换算成 ×1、×2 这种形式。

2. 怎么验证：
输入 2，蛇明显加速；输入 0.5，蛇变慢；输入 0 或负数等非法值，程序不改变速度，输入框自动弹回当前真实倍速。

3. 提示词迭代：
我让 AI 加倍速框，AI 没写输入校验。我补了一句“如果输入小于等于 0，就用默认速度”，AI 就加了判断。

### （5） 新增功能 ：无尽 / 任务模式切换
1. 怎么实现：
工具栏的「切换无尽」按钮绑定 toggleGameMode()。变量 taskMode 决定游戏目标：

任务模式（默认）：吃满 15 个就算成功，结束本局。

无尽模式：不限制食物数量，一直玩到撞墙或撞自己。

选择结果存进 localStorage，刷新后保留。

2. 怎么验证：
默认打开是任务模式，吃满 15 个自动结束并记为成功。点击「切换无尽」，吃满 15 个后不会停，可以继续吃，直到撞死。刷新页面，模式仍然是刚才选的那个。

3. 提示词迭代：
我让 AI 加模式切换，AI 只做了 UI 按钮。我提示“任务模式吃满 15 个要自动结束，无尽模式不要”，AI 就补上了 endRound(true) 的判断。

### （6） 新增功能 ：WSAD 键盘操作 + 鼠标加速交互
1. 怎么实现：

键盘：方向键和 WSAD 都能控制方向，且不分大小写。

鼠标：

左键单击长按：普通加速（80ms → 40ms）。

双击长按：超级加速（80ms → 1ms）。

右键按住：超级加速。

中键：切换手动/自动。

额外快捷键：L 键加速，空格暂停，R 重开。

为了防止方向反转冲突，用 pendingDirs 队列缓存按键，每次只取一个合法方向。

2. 怎么验证：
WSAD 和方向键都能正常转向。按住鼠标左键，蛇变快；双击左键按住，蛇极快；右键按住，也是极快。按中键能在手动和 AI 自动之间切换。

3. 提示词迭代：
我让 AI 加 WSAD 和鼠标操作，AI 一开始没处理“方向反转”问题（比如正在向右走时按左键，蛇会直接反向撞死自己）。我提示“不能直接反向，要排队缓存按键”，AI 就加了 pendingDirs 队列。



## 五、进阶挑战：Croc

### 1. 论文思路简述
Croc 是 PULP 平台推出的面向教学的 RISC-V SoC。核心是一个 CVE2 处理器，配合 OBI 总线、SRAM 和 UART 外设。它基于开源 130nm 工艺，已于 2024 年成功流片，目标是让学生跑通数字芯片从 RTL 设计到后端物理实现的完整流程。

### 2. 前端 Verilator 仿真（已成功跑通）
实际流程：在 `sw` 目录成功编译 `helloworld.c` 后，进入 `verilator` 目录执行：
`./run_verilator.sh --build --run ../sw/bin/helloworld.hex`
运行结果：终端显示 `[JTAG] Initialization success`，成功将 helloworld.hex 写入内存，`[CORE] Waking core via CLINT msip`（CPU 核心被成功唤醒并开始执行程序）。

### 3. 后端 Yosys 综合（已成功跑通）
实际流程：进入 `~/croc/yosys`，执行 `./run_synthesis.sh --synth`。
运行结果：终端显示 `Executing SLANG frontend`，随后执行了 ABC 逻辑优化、HILOMAP 技术映射等核心综合步骤。最终显示 `Build succeeded: 0 Error, 0 Warning`，并成功生成门级网表文件 `out/croc_yosys.v`。

### 4. 前端/后端各自干了什么
前端（Frontend）：负责编写 Verilog RTL 代码，定义芯片逻辑功能。使用 Verilator 进行功能仿真，验证逻辑正确性。
后端（Backend）：负责将验证过的 RTL 代码转换为物理版图。使用 Yosys 将 RTL 综合成门级网表，再用 OpenROAD 进行布局布线，最终生成可以流片的版图文件。

### 5. 踩坑记录与工程心得（重点）
跑通 Croc 的过程遇到了极大的工具链阻力，以下是修复的关键问题：

前端排错：Ubuntu 自带 RISC-V 工具链缺少 32 位库（`-lm`）；xPack 工具链与项目自带启动文件冲突（`multiple definition of '_start'`）。通过强制修改 `Makefile` 增加 `-nostartfiles`，并重写 `link.ld` 补齐 `_bss_start` 和 `_end` 解决。同时修复了 `zlib.h` 缺失问题。

后端排错：官方脚本强依赖 `slang` 插件解析 SystemVerilog 语法，但 Ubuntu 源无此包。我被迫从源码手动编译 `slang.so`。

编译 slang 插件：遭遇 CMake `FetchContent` 强制联网失败。我通过 `-DFETCHCONTENT_SOURCE_DIR_...` 参数强制指定本地依赖路径，成功编译出 `slang.so`。

修复脚本兼容性：新版 slang 废弃了 `--ignore-unknown-modules` 参数，我手动清理了 TCL 脚本中过时的参数，并指定了 `slang.so` 的绝对路径。

最终结果：前端 Verilator 仿真与后端 Yosys 综合全部成功跑通！这种真实的工程排错经验极其宝贵。
